# LLM-agent-trust-game

Spatial trust-game experiments using LLM agents, with an offline example for analysing the supplied NHB trust-game workbook.

[中文使用说明](README.zh-CN.md) · [Offline data and metrics](docs/offline-analysis.md)

## What can be reproduced?

- **Offline analysis:** read `src/outputs/2024_NHB_model_Trust Game.xlsx`, preserve the experiment observations, and export descriptive summaries without API credentials. This workbook contains 49 players and 50 rounds per session. It is a separate input dataset, not output generated by the current LLM simulation.
- **Online experiments:** run LLM agents on a periodic square grid. The current configuration uses 36 agents and 20 rounds. The treatment proportions are **[0, 0.25, 0.5, 0.75, 1]**. Online API execution has not been validated in this release because the author's DeepSeek account has no remaining credit.

The offline example explains an analysis route; it does not claim to reproduce the exact figures, significance tests, or numerical conclusions of a manuscript. The input workbook and LLM output formats differ.

## Installation

Use **Python 3.12** and run commands from the repository root. The setup below is written for Linux/macOS; on Windows activate the environment with `.venv\Scripts\activate`.

```bash
git clone https://github.com/huzyang/LLM-agent-trust-game.git
cd LLM-agent-trust-game
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

For offline workbook analysis only:

```bash
python -m pip install -r requirements-offline.txt
```

For the online simulation and legacy plotting tools as well:

```bash
python -m pip install -r requirements.txt
python -m pip check
```

The requirements files pin direct dependencies. `requirements-lock.txt` records the complete environment used for the local checks; install it with `python -m pip install -r requirements-lock.txt` if you need that exact package set. These are newly checked reproduction dependencies, **not a recovered environment from the historical experiments**. GPU hardware and local model weights are not required by the API-based simulation.

## Quick start: offline analysis

The workbook must exist at the path shown below. Paths containing spaces must be quoted.

```bash
python -m src.analysis.nhb_analysis \
  --input "src/outputs/2024_NHB_model_Trust Game.xlsx" \
  --output-dir outputs/nhb_offline
```

The script selects the 15 `TG <percent>% free session<number>` sheets and ignores the `Participant information` sheet. It does not deduplicate equal monetary amounts, average different sessions by player ID, or overwrite the input workbook.

Expected input and output sizes for the supplied workbook:

| Item | Expected size |
| --- | --- |
| Experiment sheets | 15: five treatments × three sessions |
| Rows per experiment sheet | 2,450: 49 players × 50 rounds |
| `player_round.csv` | 36,750 player-round observations |
| `directed_amounts.csv` | 147,000 observations: four directions per player-round |
| `session_round_metrics.csv` | 750 treatment-session-round summaries |
| `round_summary.csv` | 250 treatment-round summaries |

`sheet_inventory.csv` describes the input sheets. `manifest.json` records the workbook SHA-256, row counts, aggregation rule, and number of groups with undefined Gini values. See [offline-analysis.md](docs/offline-analysis.md) for field definitions, indicator formulas, and a plotting example.

## Online experiment setup

1. Install `requirements.txt` (or the full lock file).
2. Copy the credential template and edit the new file:

   ```bash
   cp .env.example .env
   ```

   Supply `DEEPSEEK_API_KEY`, `DEEPSEEK_API_BASE_URL`, and `DEEPSEEK_MODEL` using your provider's credentials, OpenAI-compatible endpoint, and available model identifier. The historical default label is `deepseek-v4-flash`; it is not a guarantee that your provider currently offers it. `.env` is ignored by Git. Do not put credentials in experiment JSON files.

3. Check the configuration without credentials or API calls:

   ```bash
   python -m src.experiment.run_main --config configs/paper.json --dry-run
   python -m src.experiment.run_main --config configs/smoke.json --dry-run
   ```

   Dry-run validates the configuration and reports planned agent-stage calls. It does **not** verify authentication, model availability, remote responses, or API credit.

4. Once your account has credit, run the small online example first:

   ```bash
   python -m src.experiment.run_main --config configs/smoke.json
   ```

   This configuration has nine agents, one treatment, and one round: 18 agent-stage calls before retries. Check its log and dialogue JSON before starting a full run.

5. Run the full configuration:

   ```bash
   python -m src.experiment.run_main --config configs/paper.json
   ```

   Output goes to root-level `outputs/`, including a log, a credential-free configuration JSON, per-run dialogue JSON files, an agent-round CSV, and a pair-data XLSX. Historical files under `src/outputs/` are separate from newly generated files.

### Experiment settings

| Setting | Current full configuration |
| --- | --- |
| Agents / grid | 36 / 6 × 6 periodic Von Neumann grid |
| Free-player proportions | 0, 0.25, 0.5, 0.75, 1 |
| Rounds per treatment | 20 |
| Iterations per treatment | 1 |
| BDI reporting | Disabled |
| Total-round information in prompt | Disabled |
| Temperature | 1.0 |
| Maximum output tokens | 131,072; check your provider's supported limit |
| Model | `.env` / `DEEPSEEK_MODEL` |
| Prompt template | `src/prompts/all_prompts.json` |

Only the five treatment proportions have been confirmed as the paper defaults. Other settings retain the current code defaults and should be checked against the final manuscript. To run three repetitions, copy `configs/paper.json`, set `iterations` to `3`, and pass the copy via `--config`. Do not silently treat the current one-iteration configuration as three repeats.

One full run plans 7,200 agent-stage calls per model, excluding retries. Three iterations plan 21,600. Actual SDK requests, token usage, elapsed time, and charges depend on your provider, conversation history and retries; dry-run does not estimate money.

The code runs an investor stage and a trustee stage in each round, exchanging decisions with four neighbors. Free players can differentiate decisions across neighbors; constrained players follow the restrictions enforced by the prompts and decision validation. Read `src/experiment/agents.py` for payoff calculations and `src/experiment/model.py` for parsing and constraint enforcement.

### Online limitations

- Online API execution is unverified due to lack of credit. Successful installation, imports, or dry-run do not establish online reproducibility.
- Role assignment uses random shuffling without an explicit reproducible seed. Remote model responses can also vary. Record the code commit, configuration, prompt version, service endpoint, model identifier, call date, and all raw responses for each experiment.
- On API failure the current implementation can log an error and substitute zero decisions. Inspect logs and dialogue records containing `ERROR`; do not interpret such decisions as normal model behavior without an explicit analysis rule.
- A model or SDK token limit may reject a requested `max_tokens`. Change the copied configuration to a supported value and report the change.
- The existing three-run averaging script and legacy plotting entry point contain historical paths and require adaptation. For type-specific analyses, aggregate within each independent run before combining runs; player IDs and role assignments are not interchangeable across repetitions.

## Pair-data export without deduplication

For an online pair-data XLSX (columns `proportion`, `sent_amount`, `returned_amount`):

```bash
python -m src.analysis.pair_data_analysy \
  --input "outputs/your_run/your_pair_data.xlsx" \
  --output outputs/pair_plot_data.xlsx
```

All transactions remain in the exported `group_sent` and `group_return` sheets, including identical amounts on different links. The NHB workbook is handled by `nhb_analysis`, which first reads its different schema.

## Troubleshooting

- **`No module named src`:** change into the repository root and use `python -m ...`, rather than running an individual file by path.
- **Missing workbook:** verify `src/outputs/2024_NHB_model_Trust Game.xlsx` exists and that paths with spaces are quoted.
- **Missing `DEEPSEEK_API_KEY` / endpoint:** fill `.env` or export those variables. Offline analysis does not need either.
- **`FastMCP` import error:** install the pinned full requirements; the CAMEL version used here requires the MCP 1.x API.
- **401 / 402 / model not found:** check credentials, balance, endpoint, and the exact model identifier with your provider. Do not repeatedly launch the full experiment to diagnose authentication.
